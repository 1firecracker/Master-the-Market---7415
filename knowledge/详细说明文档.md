## 概述

`baseline.py` 是一个基于均值回归的单标的量化交易策略，使用 ALGOGENE 平台进行回测。策略核心思想是：当价格偏离历史均值时，预期价格会回归到均值，从而产生交易机会。

**策略类型：** 均值回归策略（Mean Reversion）  
**标的数量：** 1个  
**数据频率：** 日线数据  
**回测窗口：** 最近5个交易日

### 2. `start(self, mEvt)` - 策略启动函数

**作用：** 策略初始化，获取订阅标的，启动回测引擎

**执行时机：** 回测开始时，由 ALGOGENE 平台自动调用一次

**参数说明：**

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `mEvt` | `dict` | 包含策略配置信息的字典 |

**`mEvt` 字典结构：**

```python
mEvt = {
    'subscribeList': ['0005.HK'],  # 订阅的标的列表
    # ... 其他配置信息
}
```

**`mEvt['subscribeList']` 说明：**
- **类型：** `list`
- **内容：** 字符串列表，每个元素是一个标的代码
- **格式：** `['0005.HK']` 或 `['0005.HK', '0939.HK']`
- **索引：** `[0]` 表示第一个标的

**代码详解：**

```python
def start(self, mEvt):
    # 获取第一个订阅标的（单标的策略）
    self.myinstrument_Y = mEvt['subscribeList'][0]
    
    # 创建回测事件处理器
    self.evt = AlgoAPI_Backtest.AlgoEvtHandler(self, mEvt)
    
    # 启动回测引擎
    self.evt.start()
```

**执行流程：**
1. 从 `subscribeList` 获取第一个标的代码，赋值给 `self.myinstrument_Y`
2. 创建 `AlgoEvtHandler` 对象，传入当前策略实例和配置
3. 调用 `start()` 启动回测引擎

**注意事项：**
- 必须确保 `subscribeList` 至少有一个元素，否则会报 `IndexError`
- `AlgoEvtHandler` 会监听市场数据并调用相应的回调函数

### 3. `on_bulkdatafeed(self, isSync, bd, ab)` - 批量数据回调函数

**作用：** 接收市场数据，执行策略逻辑，生成交易信号

**执行时机：** 每当有新的市场数据时，由 ALGOGENE 平台自动调用

**参数说明：**

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `isSync` | `bool` | 是否为同步数据（所有订阅标的的数据都已更新） |
| `bd` | `dict` | 批量数据字典，包含所有订阅标的的市场数据 |
| `ab` | `dict` | 账户余额信息（Account Balance） |

**`bd` 字典结构：**

```python
bd = {
    '0005.HK': {
        'timestamp': datetime(2020, 1, 2, 8, 0, 0),  # 时间戳
        'lastPrice': 45.26,                           # 最新价格（收盘价）
        'open': 45.26,                                # 开盘价
        'high': 45.34,                                 # 最高价
        'low': 45.08,                                 # 最低价
        'close': 45.30,                               # 收盘价
        'volume': 14629077,                           # 成交量
        # ... 其他字段
    }
}
```

**`ab` 字典结构：**

```python
ab = {
    'cash': 1000000.0,        # 可用现金
    'totalAsset': 1000000.0,  # 总资产
    'margin': 0.0,            # 已用保证金
    # ... 其他账户信息
}
```

**代码逻辑详解：**

#### 3.1 数据同步检查
```python
if isSync:
```
- **作用：** 确保所有订阅标的的数据都已更新
- **原因：** 避免使用不完整的数据进行计算

#### 3.2 交易频率控制
```python
if bd[self.myinstrument_Y]['timestamp'] >= self.lasttradetime + timedelta(hours=24):
    self.lasttradetime = bd[self.myinstrument_Y]['timestamp']
```
- **作用：** 确保每天只交易一次
- **逻辑：** 只有当新数据的时间戳距离上次交易时间超过24小时时才处理
- **`timedelta(hours=24)`：** 表示24小时的时间间隔

#### 3.3 数据收集
```python
self.arr_closeY.append(bd[self.myinstrument_Y]['lastPrice'])
```
- **作用：** 将当前价格添加到历史价格列表
- **`lastPrice`：** 最新成交价（通常是收盘价）

#### 3.4 滚动窗口管理
```python
if len(self.arr_closeY) > self.arrSize:
    self.arr_closeY = self.arr_closeY[-self.arrSize:]
```
- **作用：** 保持窗口大小为 `arrSize`（5天）
- **逻辑：** 如果列表长度超过5，只保留最后5个元素
- **`[-self.arrSize:]`：** 列表切片，取最后5个元素

#### 3.5 样本充足性检查
```python
if len(self.arr_closeY) < 2:
    return
```
- **作用：** 确保有足够的数据进行回归分析
- **原因：** OLS回归至少需要2个数据点

#### 3.6 OLS回归分析
```python
Y = self.arr_closeY
X = [1.0] * len(Y)
model = sm.OLS(Y, X)
results = model.fit()
```
- **作用：** 使用OLS回归估计均值
- **模型：** `Y = β × 1`，即 `Y = β`（常数项）
- **结果：** `β` 就是价格的均值
- **`X = [1.0] * len(Y)`：** 创建全为1的列表作为自变量

**回归模型说明：**
- **无截距回归：** `Y ~ X`，其中 X 全为1
- **等价于：** 计算 Y 的均值
- **数学表达：** `mean(Y) = ΣY / n`

#### 3.7 提取回归结果
```python
mean_level = results.params[-1]  # 常数项 = 均值
mse = results.mse_resid           # 残差均方误差
```

**`results.params` 说明：**
- **类型：** `numpy.ndarray`
- **内容：** 回归系数数组
- **`[-1]`：** 取最后一个元素（唯一的系数，即均值）

**`results.mse_resid` 说明：**
- **类型：** `float`
- **含义：** 残差的均方误差（Mean Squared Error）
- **公式：** `MSE = Σ(Y - Ŷ)² / (n - k)`，其中 k 是参数个数
- **用途：** 衡量价格波动程度，用于设置交易阈值

#### 3.8 计算价格偏离
```python
diff = self.arr_closeY[-1] - mean_level
```
- **作用：** 计算当前价格与均值的偏离程度
- **`[-1]`：** 取列表最后一个元素（最新价格）
- **`diff > 0`：** 价格高于均值
- **`diff < 0`：** 价格低于均值

#### 3.9 生成交易信号
```python
if diff > 0.1 * mse:  # 价格高于均值，做空
    self.orderPairCnt += 1
    self.openOrder(-1, self.myinstrument_Y, self.orderPairCnt, 1)
elif diff < -0.1 * mse:  # 价格低于均值，做多
    self.orderPairCnt += 1
    self.openOrder(1, self.myinstrument_Y, self.orderPairCnt, 1)
```

**交易逻辑：**
- **阈值：** `±0.1 × MSE`
- **做空条件：** `diff > 0.1 × MSE`（价格显著高于均值）
- **做多条件：** `diff < -0.1 × MSE`（价格显著低于均值）
- **预期：** 价格会回归到均值，从而获利

**阈值选择说明：**
- `0.1` 是一个经验值，可以根据回测结果调整
- 阈值太小：交易频繁，可能产生过多噪音
- 阈值太大：交易机会少，可能错过盈利

### 4. `openOrder(self, buysell, instrument, orderRef, volume)` - 下单函数

**作用：** 创建并发送交易订单

**执行时机：** 由策略逻辑调用（非平台回调）

**参数说明：**

| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `buysell` | `int` | 买卖方向：1=买入，-1=卖出 | `1` 或 `-1` |
| `instrument` | `str` | 标的代码 | `'0005.HK'` |
| `orderRef` | `int` | 订单引用号（用于标识相关订单） | `1, 2, 3...` |
| `volume` | `float` | 交易数量（手数） | `1.0` |

**代码详解：**

#### 4.1 创建订单对象
```python
order = AlgoAPIUtil.OrderObject()
```
- **作用：** 创建订单对象
- **类型：** `AlgoAPIUtil.OrderObject`

#### 4.2 设置订单属性

| 属性 | 类型 | 说明 | 可选值 |
|------|------|------|--------|
| `instrument` | `str` | 交易标的代码 | `'0005.HK'` |
| `orderRef` | `int` | 订单引用号 | 任意整数 |
| `volume` | `float` | 交易数量 | 正数 |
| `openclose` | `str` | 开仓/平仓 | `'open'` 或 `'close'` |
| `buysell` | `int` | 买卖方向 | `1`（买入）或 `-1`（卖出） |
| `ordertype` | `int` | 订单类型 | `0`（市价单）或 `1`（限价单） |
| `holdtime` | `int` | 持仓时间（秒） | 正整数 |

**属性详细说明：**

**`order.instrument`：**
- 必须与 `_meta_.json` 中定义的标的代码完全匹配
- 示例：`'0005.HK'`、`'0939.HK'`

**`order.orderRef`：**
- 用于标识一组相关订单（如配对交易中的两个订单）
- 相同 `orderRef` 的订单可以关联管理
- 通常使用递增的计数器

**`order.volume`：**
- 交易数量，单位取决于合约设置
- 对于股票，通常是股数或手数
- 可以是小数（如 `1.5` 手）

**`order.openclose`：**
- `'open'`：开仓（建立新头寸）
- `'close'`：平仓（关闭已有头寸）
- 本策略使用 `'open'`，因为每次都是新开仓

**`order.buysell`：**
- `1`：买入（做多）
- `-1`：卖出（做空或平多）
- 注意：卖出需要平台允许做空

**`order.ordertype`：**
- `0`：市价单（Market Order）
  - 以当前市场价格立即成交
  - 成交价格不确定，但成交速度快
- `1`：限价单（Limit Order）
  - 需要设置 `order.price` 属性
  - 只有价格达到设定值才成交
  - 可能无法成交

**`order.holdtime`：**
- 单位：秒
- 作用：自动平仓时间
- 本策略：`5 × 24 × 60 × 60 = 432000` 秒（5天）
- 到期后，平台会自动平仓

#### 4.3 发送订单
```python
self.evt.sendOrder(order)
```
- **作用：** 将订单提交给回测引擎
- **执行：** 平台会检查订单有效性、资金充足性等
- **结果：** 订单可能立即成交、排队等待或被拒绝

**订单执行流程：**
1. 检查资金是否充足
2. 检查是否允许做空（如果是卖出）
3. 检查持仓是否足够（如果是平仓）
4. 执行撮合（市价单立即成交，限价单等待价格）
5. 更新账户余额和持仓
6. 触发 `on_orderfeed` 回调（如果实现）

## 策略逻辑流程

### 完整执行流程

```
1. 平台启动回测
   ↓
2. 调用 start(mEvt)
   - 获取订阅标的
   - 创建事件处理器
   - 启动回测引擎
   ↓
3. 平台推送市场数据
   ↓
4. 调用 on_bulkdatafeed(isSync, bd, ab)
   ↓
5. 检查数据同步和交易频率
   ↓
6. 收集价格数据（滚动窗口）
   ↓
7. 检查样本充足性
   ↓
8. OLS回归分析
   - 估计均值
   - 计算MSE
   ↓
9. 计算价格偏离
   ↓
10. 判断是否触发交易信号
    ↓
11. 如果触发，调用 openOrder()
    - 创建订单对象
    - 设置订单属性
    - 发送订单
    ↓
12. 平台执行订单
    - 检查资金
    - 撮合成交
    - 更新账户
    ↓
13. 重复步骤3-12，直到回测结束
```

## 常见问题

### Q1: 为什么使用 `isSync` 检查？

**A:** 确保所有订阅标的的数据都已更新，避免使用不完整的数据进行计算。

### Q2: 为什么每天只交易一次？

**A:** 通过 `timedelta(hours=24)` 控制交易频率，避免过度交易和噪音。

### Q3: 为什么使用 OLS 回归而不是直接计算均值？

**A:** 
- 保持与配对交易策略的一致性
- 可以方便地获取 MSE（用于设置阈值）
- 未来可以扩展为更复杂的回归模型

### Q4: 阈值 `0.1 × MSE` 如何选择？

**A:** 
- 这是一个经验值
- 可以通过回测优化找到最佳阈值
- 建议范围：`0.05 × MSE` 到 `0.2 × MSE`

### Q5: 订单被拒绝怎么办？

**A:** 
- 检查资金是否充足
- 检查是否允许做空
- 检查持仓是否足够（平仓时）
- 查看 Console 日志了解拒绝原因
